## 3. Test audit — THE GATE. Nothing in section 4 starts until this is done.

**This is the change's principal risk and the one most likely to do lasting
damage.** Deleting ~400 lines of machinery deletes the tests that covered it.
Some of those tests assert a *mechanism* that is genuinely gone; others assert a
*guarantee* that still holds and must keep its coverage. The two look alike
because both live in files named after the racing executor. A guarantee that
silently loses its test leaves a passing suite, a green coverage gate, and no
protection — and nothing later in this change would detect it.

The blast radius, counted rather than estimated:

| File | Tests | Lines |
|---|---|---|
| `tests/test_racing_encounter_order.py` | 44 | 772 |
| `tests/test_racing_delivery_order.py` | 41 | 614 |
| `tests/test_execution_model.py` | 27 | 472 |
| `tests/test_parallel.py` | 13 | 186 |
| **Total in the four named files** | **125** | **2044** |

Plus scattered references to doomed names in `test_find_first.py`,
`test_unordered.py`, `test_for_each_ordered.py`, `test_package_exports.py`,
`test_name_visibility.py`, and — note especially — `conftest.py`, which
references `PROCESSES` and so may carry a shared fixture that several files
depend on.

- [x] 3.1 Build the inventory **before touching any test**. List every test in the four files above, plus every test elsewhere referencing `_Window`, `_guarded`, `_group_through`, `_release_in_order`, `_run_ordered_tail`, `_racing_branches`, `_race_through`, `_IN_FLIGHT_PER_WORKER`, `_in_flight`, `RACING` or `PROCESSES`. Verify the count reconciles with the table; a discrepancy means the grep missed something.
- [x] 3.2 Classify every test in the inventory by **one rule, applied to each individually**: does it assert a requirement that survives in `openspec/specs/`? Name the requirement.
  - **Maps to a surviving requirement** → it asserts a *guarantee*. It MUST be rewritten against fork/join, not deleted. Encounter order, short-circuiting, `unordered()`'s effect, global correctness of `distinct`/`limit`/`skip`, and the read-ahead bound staying private are all guarantees.
  - **Maps to a requirement this change removes** → it asserts a *mechanism*. Safe to delete, and the removed requirement is the justification.
  - **Maps to no requirement at all** → stop. Either the test was covering something unspecified (in which case the spec has a gap this change must not paper over) or it is genuinely mechanism-only. Decide explicitly and record which; do not default to deleting.
